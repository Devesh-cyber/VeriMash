01 / THE PROBLEM

Two blockchains.
No shared record of truth.

Blockchains maintain their own transaction histories. When an application on Blockchain B receives a message claiming that something happened on Blockchain A, it cannot simply look inside Chain A and confirm that claim.

Accepting an unchecked message can create serious problems: an attacker might replay a message that was already delivered, change its contents, impersonate an authorized sender, or bypass the approvals required by the destination application.

The real challenge is not moving data between networks. It is giving the receiving application enough trustworthy evidence to decide whether that data should be accepted.

02 / OUR APPROACH

Don't just deliver.
Verify before accepting.

VeriMash v2 removes the middleman. The user signs the source transaction on Blockchain A in their own wallet. Three validators, each on a separate machine with its own private key and its own RPC provider, wait for block confirmations and independently check the receipt, block hash and event.

Each validator then submits its own vote directly to Blockchain B. There is no relay to trust: the destination contract counts the votes itself and delivers the message only when two of three agree on exactly the same content. Forged, altered and replayed messages are rejected on-chain.

Every delivery can be inspected in the Transaction Explorer, from the source transaction through each validator vote. VeriMash is a prototype on public test networks: validators are honest-majority, and it does not transfer real cryptocurrency.

03 / HOW IT WORKS

From event to evidence.

Follow one message from its original on-chain event to an auditable destination result. Each completed stage in the live demo corresponds to actual test-chain transaction evidence; the displayed proof is not a fabricated animation.

01

Sign on Chain A

The user sends a message from their own wallet on Blockchain A. The transaction emits a MessageSent event with the message, the sender and a unique nonce.

02

Verify independently

Each of three validators reads Blockchain A through its own RPC, waits for confirmations, and checks the receipt, block hash and event for itself.

03

Vote on Chain B

Each validator submits its own vote straight to the gate on Blockchain B. A vote is bound to the exact message, sender, nonce and both chains.

04

Deliver at 2 of 3

When two validators agree, the gate itself delivers the message and emits an auditable receipt. No relay, no admin key, delivered exactly once.
